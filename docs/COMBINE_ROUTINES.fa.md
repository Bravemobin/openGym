# ترکیب برنامه‌ها — اجرای بیش از یک روال تمرینی در یک جلسه

مشخصات فنی و قابل پیاده‌سازی برای **ترکیب برنامه‌های تمرینی (Combine routines)**: اجرای بیش از یک روال تمرینی (Routine) در یک جلسه تمرین واحد. با دو نقطه ورود — افزودن موقت «Add a routine» از طریق سربرگ تمرین، و تعریف روزهایی در برنامه‌ریز هفتگی که شامل چند روال هستند — به علاوه یک هلپر ادغام مشترک و بررسی تمامی توابعی که ساختار داده آن‌ها تغییر می‌کند.

منشأ و مستندات طراحی: تیکت Linear با شناسه [ENG-9](https://linear.app/factical/issue/ENG-9) و تیکت‌های تصمیم‌گیری زیرمجموعه آن شامل ENG-10 (فهرست توابع خواننده داده)، ENG-11 (معناشناسی `noProg`)، ENG-12 (سطوح رابط کاربری)، ENG-14 (قوانین پایدار مدل داده) و ENG-15 (اثر انگشت برنامه / مربی هوش مصنوعی). این سند راهنمای تجمیع‌شده پیاده‌سازی است و مشخصات آنچه باید ساخته شود را بیان می‌کند.

## ۱. مدل داده (Model)

**مدل A — بدون تعریف موجودیت جدید.** یک نشست ترکیبی، حاصل الحاق (Concatenation) ردیف‌های تمرینی برگرفته از N روال است. هیچ شیء «روال ترکیبی» مستقلی وجود ندارد؛ چیزی فراتر از آنچه یک نشست تک‌روال ذخیره می‌کرد ذخیره نمی‌شود، بلکه داده‌ها گسترش یافته‌اند.

- **اسلات‌های روزهای برنامه‌ریز هفتگی یک آرایه نگه می‌دارند:** فیلد `S.week[weekday]` تبدیل به `string[]` می‌شود (شناسه‌های روال‌ها، به ترتیب ادغام). فیلد `S.dayPlan[iso]` **به‌صورت اسکالر باقی می‌ماند** — جایگزینی روزانه اختصاصی و ساعت شروع همچنان تک‌گزینه‌ای هستند (ENG-12).
- **نشست فعال روال‌های خود را رصد می‌کند:** متغیر `s.active.routineId` حذف می‌شود؛ به جای آن `s.active` دارای آرایه `routineIds: string[]` خواهد شد و هنگام ادغام، یک مشخصه `rid` روی تک‌تک آیتم‌های `active.entries[]` ثبت می‌شود.
- **تمرینات ذخیره‌شده این ساختار را بازتاب می‌دهند:** متغیر `w.routineId` تبدیل به `w.routineIds: string[]` می‌شود همراه با فیلد آینه‌ای برای سازگاری عقب‌رو `w.routineId = routineIds[0]`؛ هر ورودی ذخیره‌شده شناسه `rid` خود (و پرچم `noProg` خود، به بخش ۶ مراجعه کنید) را به همراه دارد.
- **بدون نیاز به مهاجرت اجباری پایگاه داده (No migration pass):** توابع خواننده با فرمت قدیمی سازگارند: یک رشته متنی ساده به عنوان یک آرایه تک‌عضوی تلقی می‌شود. نمایه‌های موجود هرگز بازنویسی نمی‌شوند.
- **ادغام = الحاق به ترتیب روال‌ها** (همان ترتیبی که روال‌ها در برنامه‌ریز انتخاب شده‌اند یا حین تمرین اضافه گشته‌اند). تغییر چیدمان حین تمرین جزئیات دقیق‌تر را پوشش می‌دهد.
- **تمرین تکراری = شناسه تمرین یکسان (`id`) در چند روال:** در نسخه ۱، تمام تمرینات حفظ می‌شوند — بدون حذف تکراری‌ها یا نمایش رابط انتخاب.
- **افزودن دو بار یک روال تمرینی مسدود است** (روال‌هایی که هم‌اکنون در نشست وجود دارند به صورت غیرفعال نمایش داده می‌شوند). این کار همچنین ریسک تداخل شناسه گروه‌های سوپرست (`sg`) را برطرف می‌کند.

### ۱.۱ چهار ساختار داده و توابع خواننده آن‌ها

بر اساس [فهرست توابع خواننده](https://linear.app/factical/issue/ENG-10): ۷۴ نقطه در ۲۱ فایل کد (غیر تست)، که **۶۱ مورد نیازمند تغییر کد هستند**. جدول تفکیکی آن به عنوان چک‌لیست مهاجرت است؛ گروه‌های حیاتی عبارتند از:

| ساختار داده | تغییر | نحوه برخورد توابع خواننده |
|---|---|---|
| **S1** مقدار `S.week[d]` | شناسه اسکالر → `string[]` | ۴۴ نقطه: ۱۷ محل نوشتن ساختار جدید، تبدیل هلپرهای جمع، ۱۱ خواندن سازگار با آرایه، ۴ نوشتن سازگار با آرایه (حذف از لیست + حذف کلید در صورت خالی شدن). فیلد `S.dayPlan` **مستثنی است** و اسکالر می‌ماند. |
| **S2** متغیر `s.active.routineId` | → `routineIds: []` + فیلد `rid` برای هر ورودی | ۲۴ نقطه: توابع نویسنده `beginWorkout` / `beginBackfill`، ۹ نقطه خواندن `rid` در هر ورودی (تعویض، تنظیمات پیشرفت، افزودن تمرین)، ۶ نقطه فراخوانی کلاستر `startFlow`. |
| **S3** متغیر `w.routineId` | → `routineIds: []` + فیلد آینه‌ای `routineId` | ۶ نقطه. تنها آیکون گرافیکی در `WorkoutRow` آن را می‌خواند که با فیلد آینه‌ای پوشش داده می‌شود. تابع `buildCompletedWorkout` تنها نویسنده آن است. |
| **S4** متغیرهای `effectiveRoutineId` / `effectiveRoutine` / `nextTrainingDay` | توابع اصلی مبتنی بر جمع + توابع پوسته تکین | ۱۰ نقطه فراخوانی (۲ مورد داخلی در `history.js`، ۸ مورد در `sheets.jsx`، `mobile.js`، `TabBar.jsx`، `Workout.jsx` و `Home.jsx`). |

**نکات حساسی که پیاده‌سازی نباید در آن‌ها دچار خطا شود** (لیست کامل در ENG-10): صدق منطقی آرایه خالی (`[]` در جاوااسکریپت Truthy است — نویسنده‌ها باید کلید را `delete` کنند نه اینکه `[]` ذخیره نمایند)؛ مقایسه‌های `=== id` که در برابر یک آرایه بی‌پاسخ می‌مانند؛ فیلتر هم‌ارزی شیء در `views/Workout.jsx:35`؛ تبدیل رشته‌ای آرایه در `hashPlan` (بخش ۷).

## ۲. ماژول کمکی ادغام (Merge Helper)

**ماژول جدید `frontend/src/lib/session-merge.js`**، به همراه تست‌های متناظر در `session-merge.test.js`. تابع `buildSessionEntries` را از `lib/session-start.js` وارد می‌کند؛ به جز `sheets.jsx` و `views/Workout.jsx` فایل دیگری آن را ایمپورت نمی‌کند، بنابراین وابستگی چرخه‌ای (Cycle) وجود ندارد.

```js
import { buildSessionEntries } from './session-start.js'

// ساخت ورودی‌های یک نشست از روی لیستی مرتب از شناسه‌های روال‌ها.
// - فیلتر و حل به روال‌های موجود، حذف شناسه‌های تکراری (اولین روال برنده است)
// - الحاق ورودی‌های هر روال به ترتیب لیست
// - ثبت entry.rid = <شناسه آن روال> روی تک‌تک ورودی‌ها
// خروجی: { entries, routineIds, routines }
export function buildCombinedEntries(st, routineIds) {
  const seen = new Set()
  const routines = [].concat(routineIds ?? [])
    .filter(id => id && !seen.has(id) && seen.add(id))
    .map(id => st.routines.find(r => r.id === id))
    .filter(Boolean)
  const entries = routines.flatMap(r =>
    buildSessionEntries(st, r).map(e => ({ ...e, rid: r.id }))
  )
  return { entries, routineIds: routines.map(r => r.id), routines }
}

// قانون نام‌گذاری بر اساس ENG-12. نام‌ها به ترتیب ادغام:
// ۱ تا ۳ روال: پیوند با " + "         → "Rehab + Core"
// ۴ روال یا بیشتر: دو تای اول + تعداد باقی‌مانده → "Rehab + Core + 2 more"
export function deriveSessionName(names) {
  if (!names.length) return null
  if (names.length <= 3) return names.join(' + ')
  return `${names[0]} + ${names[1]} + ${names.length - 2} more`
}
```

تابع `buildSessionEntries(st, r)` (در `lib/session-start.js`) در همین تغییر بازنویسی می‌شود:

- **یک آرایه ساده `entries` برمی‌گرداند** — پوسته `{ entries, excluded }` بازنشسته می‌شود (ENG-11). فراخوان‌هایی که از `excluded` استفاده می‌کردند اکنون از پرچم `noProg` برای هر ورودی استفاده می‌کنند.
- مقدار `noProg = r?.excludeFromProgression === true` را محاسبه می‌کند و در هر کجایی که قبلاً `excluded` استفاده می‌شد اعمال می‌نماید، و پرچم `entry.noProg = true` را **تنها روی ورودی‌های مستثنی‌شده** ثبت می‌کند.
- مقدار `rid` را ثبت **نمی‌کند** — هلپر ادغام این کار را انجام می‌دهد، بنابراین همان بیلدر برای هر دو مسیر تک‌روال و ترکیبی بدون تغییر خدمت‌رسانی می‌کند.

تمامی مسیرهای شروع تمرین از طریق `buildCombinedEntries` عبور می‌کنند، از جمله شروع یک روال منفرد (یک آرایه تک‌عضوی) و تمرین آزاد (یک آرایه خالی → `entries: []`، بدون `rid`).

## ۳. جریان‌های نقطه ورود (Entry-point flows)

دقیقاً دو روش برای ساخت یک نشست ترکیبی وجود دارد:

### ۳.۱ حین تمرین — منوی سربرگ تمرین ⋮ ← Add routine

منوی `openViewMenu` در `views/Workout.jsx` بازسازی می‌شود (ENG-12 §3):

- اولین آیتم منو: **Add routine** (آیکون مثبت `plus`، زیرعنوان "افزودن روال دیگر به این نشست").
- یک ردیف **Layout** (آیکون فهرست `list`، زیرعنوان = نام چیدمان فعلی) یک **برگه تو در تو (Nested sheet)** شامل گزینه‌های کارتی / فهرستی / فشرده را باز می‌کند.
- برگه انتخاب روال: روالی که قبلاً در نشست وجود دارد به‌صورت غیرفعال همراه با برچسب `already added` نمایش داده می‌شود؛ روال بدون تمرین به‌صورت غیرفعال با برچسب `no exercises` نشان داده می‌شود. با انتخاب یک روال مجاز: ورودی‌ها الحاق می‌شوند، شناسه‌ها اضافه می‌گردند، نام جلسه با `deriveSessionName` به‌روز می‌شود و پیام اعلان ظاهر می‌گردد.

### ۳.۲ برنامه هفتگی — یک روز با چند روال به‌صورت درون‌خطی

در `views/Plan.jsx` بخش "Week schedule":

- هر ردیف روز هفته، روال‌های تخصیص‌یافته به خود را به صورت زیرردیف‌هایی در زیر سربرگ روز نمایش می‌دهد که همواره قابل مشاهده هستند.
- هر زیرردیف یک دکمه حذف سریع **✕** دارد که آن روال را از آن روز حذف می‌کند.
- روز دارای برنامه، یک ردیف اقدام **＋ Add routine** دارد که با زدن آن روال جدید به انتهای آن روز افزوده می‌شود.
- یک **روز خالی و استراحت** همچنان یک ردیف تک‌خطی باقی می‌ماند که تپ روی آن اولین روال را تعیین می‌کند.
- حذف آخرین روال از یک روز، کلید مربوط به آن روز را کاملاً پاک (`delete`) می‌کند تا آرایه خالی ذخیره نشود.

شروع تمرین با یک تپ در کارت امروز (`views/Home.jsx`): زمانی که روز هفته شامل ۲ روال یا بیشتر باشد، شروع تمرین همان جلسه ترکیبی را آغاز می‌کند.

### ۳.۳ توابع `startFlow` / `beginWorkout` / `beginBackfill`

```js
export function startFlow(routineIds) {
  bwSheet({ required: true, onDone: bw => beginWorkout(routineIds, bw) })
}

export function beginWorkout(routineIds, bw) {
  const st = S()
  const { entries, routineIds: rids, routines } = buildCombinedEntries(st, routineIds)
  update(s => {
    s.active = {
      id: uid(), d: todayISO(), start: Date.now(),
      routineIds: rids,
      name: routines.length ? deriveSessionName(routines.map(r => r.name)) : t('Freestyle'),
      bw: bw || null, cur: 0, entries,
      workoutView: st.workoutView || 'cards',
    }
  })
  useUI.getState().stopRest()
  nav('/workout')
}
```

- متغیرهای `s.active.routineId` و `s.active.excludeFromProgression` دیگر نوشته نمی‌شوند (حذف شده‌اند).
- تابع `beginBackfill` تک‌روال باقی می‌ماند اما فرمت داده خروجی آن به ساختار جدید تطبیق داده می‌شود.

## ۴. هلپرهای برنامه‌ریز هفتگی (Plural helpers)

فایل `frontend/src/lib/history.js` توابع اصلی جمع را دریافت می‌کند؛ توابع مفرد به عنوان پوسته‌های ساده روی آن‌ها باقی می‌مانند:

```js
export function effectiveRoutineIds(S, iso) {
  const ov = S.dayPlan[iso]
  if (ov === 'rest') return []
  if (ov && S.routines.some(r => r.id === ov)) return [ov]      // dayPlan اسکالر می‌ماند
  const wd = new Date(iso + 'T12:00:00').getDay()
  return [].concat(S.week[wd] || []).filter(id => S.routines.some(r => r.id === id))
}
export function effectiveRoutines(S, iso) {
  return effectiveRoutineIds(S, iso).map(id => S.routines.find(r => r.id === id)).filter(Boolean)
}
export const effectiveRoutineId = (S, iso) => effectiveRoutineIds(S, iso)[0] ?? null
export const effectiveRoutine   = (S, iso) => effectiveRoutines(S, iso)[0] ?? null
```

- آرایه خالی یا عدم وجود کلید به معنای **استراحت (Rest)** است. شرط بررسی روز استراحت: `effectiveRoutineIds(S, iso).length === 0`.
- تابع `plannedPerWeek` تعداد **روزها** را می‌شمارد نه روال‌ها: یک روز با چند روال تمرینی عدد **۱** شمرده می‌شود.
- پاک‌سازی هنگام حذف روال (`RoutineEdit.jsx`): شناسه حذف شده از آرایه روزها بیرون کشیده شده و در صورت خالی شدن، کلید حذف می‌شود.

## ۶. پیشرفت وزنه و خواندن مجدد نشست — مفهوم `noProg`

از [ENG-11](https://linear.app/factical/issue/ENG-11). ویژگی «مستثنی از پیشرفت وزنه» از یک پرچم کلی برای تمام جلسه تمرین به یک پرچم **به ازای هر ورودی تمرین** تبدیل می‌شود. به این ترتیب، اگر یک روال توان‌بخشی (Rehab) با تمرینات اصلی ترکیب شود، تنها تمرینات توان‌بخشی از محاسبات اضافه بار پیش‌رونده مستثنی می‌شوند و حرکات اصلی روند پیشرفت طبیعی خود را طی می‌کنند.

- **یک شرط اعتبارسنجی مشترک** صادر شده از `history.js`:
  `entryExcluded(w, entry) → w.excludeFromProgression === true || entry.noProg === true`.
- **پرچم `noProg` صرفاً از مقدار `excludeFromProgression` در روال منبع مشتق می‌شود** و روی ورودی ثبت می‌گردد. این فیلد تنها در صورت `true` بودن نوشته می‌شود.
- **تغییرات در `progression.js`:** در تابع `sessionsFor` شرط بررسی حذف به ازای هر ورودی اعمال می‌شود.
- **تغییرات در `history.js`:** تابع `lastEntryFor` در تمام فراخوانی‌ها ورودی‌های `noProg` را نادیده می‌گیرد تا «دفعه قبل» همواره به آخرین رکورد مؤثر اشاره کند.
- **رکوردهای شخصی (Best / PRs) دست‌نخورده باقی می‌مانند:** انجام یک وزنه سنگین یک واقعیت است؛ پرچم `noProg` تجویز ست‌های بعدی را متوقف می‌کند نه ثبت رکوردها را.
- تابع `buildCompletedWorkout`: فیلدهای `entry.noProg` و `entry.rid` را بر روی ورودی‌های ذخیره‌شده کپی می‌کند و فیلد سنتی `w.excludeFromProgression: true` را تنها در صورتی می‌نویسد که تک‌تک حرکات آن جلسه `noProg` باشند.
- افزودن تمرین عادی حین تمرین (Add exercise): پرچم `noProg` نمی‌گیرد زیرا حرکات دستی در پیشرفت لحاظ می‌شوند.

## ۷. مربی هوش مصنوعی — بافت خواندن و اثر انگشت برنامه

از [ENG-15](https://linear.app/factical/issue/ENG-15). اثر انگشت برنامه تمرینی در دو محیط مجزا محاسبه می‌شود که ساختار بیلد مشترکی ندارند (`frontend/src/lib/coach.js` و `api/coach/core/`) و باید بایت به بایت یکسان باشند. مستند [AI_COACH.fa.md](AI_COACH.fa.md) را ببینید.

**فرم استاندارد (Canonical form):** هر روز به یک آرایه نرمال‌سازی می‌شود:

```js
week: Object.fromEntries(
  [1,2,3,4,5,6,0].filter(d => S.week?.[d]?.length).map(d => [d, [].concat(S.week[d])])
)
```

رشته منفرد `'r1'` و آرایه `['r1']` هر دو به `['r1']` تبدیل می‌شوند، بنابراین مقادیر قدیمی و جدید بدون تمایز خواهند بود. ترتیب روال‌ها حفظ می‌شود و هرگز سورت نمی‌شود (زیرا معرف ترتیب ادغام است).

**تابع `hashPlan`:** آرایه روزها را با علامت `+` ادغام می‌کند:

```js
week: Object.keys(plan?.week || {}).sort().map(k => k + '=' + plan.week[k].join('+'))
```

مقدار `{1:['r1']}` تبدیل به `"1=r1"` می‌شود که **دقیقاً بایت به بایت با اثر انگشت قبل از آپدیت یکسان است**، بنابراین پس از ارتقای برنامه هشدارهای نادرست قدیمی بودن (Stale) صادر نمی‌شود.

پی‌لود ارسالی به مدل شامل `cleanPlan(S)` است و مدل توجیه شده است که مقادیر `plan.week` آرایه‌ای از شناسه‌ها هستند، اما پیشنهاد تغییرات هفته (`week`) از طرف مدل همواره به یک روال منفرد یا استراحت محدود است و مدل نمی‌تواند روز ترکیبی جدید اختراع کند.

---

## ۸. قوانین پایدار مدل داده (Data-model invariants)

- **قرارداد روزهای استراحت:** فیلد `S.week[wd]` آرایه‌ای از نوع `string[]` است. هیچ بخشی از برنامه نباید مقدار `[]` را ذخیره کند — حذف آخرین روال کلید را `delete` می‌کند. نبود کلید تنها تعریف استاندارد «استراحت» است.
- **فیلد `S.dayPlan[iso]` همواره اسکالر باقی می‌ماند** و هرگز آرایه نمی‌شود.
- **انتساب `rid` حین تمرین:** افزودن تمرین (`Add exercise`) شناسه `rid` آیتم جاری را به ارث می‌برد تا یکپارچگی بلاک روال در گزارش تمرین حفظ شود؛ تعویض حرکت (`Swap`) شناسه `rid` حرکت جایگزین‌شده را حفظ می‌کند. جلسات تمرین آزاد (Quick Start) مقدار `rid = null` و `plan = null` خواهند داشت.

## ۹. سطوح رابط کاربری (UI Surfaces)

- **برنامه هفتگی (Plan → Week schedule):** مدیریت زیرردیف‌های روزها به‌صورت درون‌خطی.
- **منوی سه نقطه تمرین (⋮):** افزودن روال تمرینی به عنوان گزینه نخست؛ انتقال گزینه‌های نمای کارتی/فهرستی/فشرده به زیربرگه Layout.
- **کارت امروز در صفحه خانه:** عنوان = نام ترکیبی نشست؛ آیکون = ایموجی اولین روال تمرینی.
- **تاریخچه تمرینات (WorkoutDetail):** دسته‌بندی حرکات در بخش‌های مجزا بر اساس روال منبع با سربرگ تعداد ست‌ها و حجم تمرین مربوط به آن روال. جلسات تک‌روال سنتی بدون سربرگ‌های اضافی مانند گذشته نمایش داده می‌شوند.
- **نام‌گذاری جلسات ترکیبی:** با هلپر `deriveSessionName`.

این موارد به فازهای بعدی موکول شده‌اند:
