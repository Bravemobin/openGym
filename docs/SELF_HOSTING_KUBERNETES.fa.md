# خودمیزبانی openGym روی کوبرنتیز (Kubernetes)

مانیفست‌های نمونه برای یک کلاستر کوچک، ارائه‌شده از یک ستاپ K3s همراه با Gateway API و cert-manager. ابتدا [راهنمای خودمیزبانی (SELF_HOSTING.fa.md)](SELF_HOSTING.fa.md) را مطالعه کنید: الزام کلید عبور یا Passkey (شامل HTTPS، `RP_ID`، `ORIGIN`)، تنظیمات موجود در `.env.example` و توصیه‌های پشتیبان‌گیری در اینجا نیز عیناً صدق می‌کنند.

معماری openGym بسیار سرراست است — یک بخش فرانت‌اند و یک بک‌اند API. بخش API تمام داده‌ها را در فایل‌های متنی ساده JSON روی یک Volume ذخیره می‌کند. فایل Docker Compose همچنین حاوی کانتینر سومی است که مدیا و تصاویر تمرینات را یک‌بار دانلود می‌کند؛ در اینجا این وظیفه بر عهده یک `initContainer` است. تنها چند منبع (Resource) برای ایجاد وجود دارد:

- ۲ عدد PVC: منبع `opengym-data` (کاربران، کلیدهای عبور، تمرینات، فایل‌های آپلود شده — **حتماً از این مورد نسخه پشتیبان تهیه کنید**) و `opengym-media` (تصاویر تمرینات که در صورت از دست رفتن مجدداً قابل دانلود هستند).
- ۱ عدد Deployment که جهت سادگی، کانتینر API و کانتینر وب را درون یک پاد (Pod) اجرا می‌کند. این استقرار با استراتژی `Recreate` روی یک رپلیکا (1 Replica) باقی می‌ماند: داده‌های API فایل‌هایی روی یک Volume از نوع `ReadWriteOnce` هستند و هرگز نباید دو فرآیند API به طور همزمان روی آن‌ها بنویسند.
- یک HTTPRoute (این نمونه از Gateway API استفاده می‌کند؛ تعریف Ingress به سمت سرویس `opengym` روی پورت 80 نیز کار می‌کند)، به علاوه یک گواهی cert-manager Certificate برای نام دامنه (Hostname).

```bash
git clone https://github.com/DuarteSantos8/openGym   # یا مخزن آینه‌ای https://gitlab.com/DuarteSantos8/opengym
cd openGym
# در فایل kubernetes/deployment.yaml، مقادیر RP_ID و ORIGIN را در spec.template.spec.containers[api].env
# به نام دامنه خود تنظیم کنید، و همچنین نام دامنه را در kubernetes/httproute.yaml وارد نمایید.
kubectl apply -k kubernetes/
```

نکات:

- این مانیفست‌ها فضای نام (Namespace) با عنوان `fitness` را ایجاد و استفاده می‌کنند (`kubernetes/namespace.yaml`، که توسط `kubernetes/kustomization.yaml` روی تمام منابع اعمال می‌شود؛ در صورت نیاز در هر دو نام آن را تغییر دهید)، و یک Gateway به نام `eg` در فضای نام `envoy-gateway-system` با یک شنونده `https`؛ هر دو را متناسب با کلاستر خود تنظیم کنید. Gateway باید TLS را خاتمه (Terminate) دهد؛ این پیکربندی با [Envoy Gateway](https://gateway.envoyproxy.io) و [cert-manager](https://cert-manager.io) آزمایش شده است.
- ایمیج‌های استفاده شده، ایمیج‌های منتشر شده رسمی `ghcr.io/duartesantos8/opengym-api` و `opengym-web` هستند. مربی هوش مصنوعی (AI Coach) با کلید API روی همین ایمیج API پیش‌فرض کار می‌کند؛ ارائه‌دهندگان ورود اختصاصی Claude و Codex نیاز به تارگت بیلد `coach` دارند که منتشر نمی‌شود و باید خودتان آن را بیلد کنید (به [AI_COACH.fa.md](AI_COACH.fa.md) مراجعه کنید).
- ایمیج‌ها به یک نسخه پایدار پین شده‌اند (`1.3.9`)، و ایمیج‌های API و web همواره باید به یک نسخه مشترک اشاره کنند. برای به‌روزرسانی، یادداشت‌های انتشار (Release notes) را بخوانید، نسخه جدید را روی هر دو کانتینر تنظیم کرده و دوباره اعمال کنید؛ پین کردن به `latest` ممکن است باعث شود پاد ری‌استارت شده نسخه‌ای را اجرا کند که خودتان هرگز انتخاب نکرده‌اید.
- تنظیمات به‌صورت متغیرهای محیطی روی کانتینر `api` تعریف می‌شوند و نام‌گذاری آن‌ها مطابق با فایل `.env.example` است. اطلاعات حساس مانند کلیدهای Push notification را در یک Kubernetes Secret نگهداری کرده و با `envFrom` بارگذاری نمایید.
- **آدرس آی‌پی کلاینت‌ها (Client addresses):** کانتینر وب مقدار هدر `X-Forwarded-For` را با آدرسی که درخواست از آن دریافت شده بازنویسی می‌کند (به `web/nginx.conf.template` مراجعه کنید)، و در پشت یک Gateway این آدرس متعلق به پادِ گیت‌وی است، نه بازدیدکننده واقعی. بنابراین محدودکننده ورود (Sign-in throttle) که تعداد تلاش‌ها را بر اساس آدرس می‌شمارد، بر روی کل نمونه به‌صورت یکجا اعمال می‌شود و لاگ فعالیت‌ها نیز آدرس گیت‌وی را ثبت می‌کند. گزینه `TRUST_PROXY` خاموش گذاشته شده است زیرا این وضعیت را تغییر نمی‌داد: API همان آدرس گیت‌وی را از هدر می‌خواند — و هر پادی که مستقیماً به پورت 3000 دسترسی داشته باشد می‌تواند آدرس دلخواه خود را در آن قرار دهد. به دست آوردن آدرس واقعی بازدیدکنندگان مستلزم آن است که گیت‌وی آدرس‌ها را حفظ کند (به عنوان مثال `externalTrafficPolicy: Local` روی سرویس LoadBalancer آن) و هدر اختصاصی خود را تنظیم کند که هر آنچه را که کلاینت فرستاده بازنویسی نماید؛ سپس آن را با `CF_CONNECTING_IP` روی کانتینر `web` پاس دهید (همان‌طور که در `.env.example` برای Cloudflare توضیح داده شده است)، متغیر `TRUST_PROXY=1` را روی کانتینر `api` فعال کنید و یک NetworkPolicy اضافه نمایید تا تنها پادِ کانتینرِ وب به پورت 3000 دسترسی داشته باشد.
